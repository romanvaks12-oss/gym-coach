# Решения (ADR)

Формат: `## ADR-NNN — Название` + Контекст / Решение / Последствия / Дата.
Статус: `proposed` | `accepted` | `superseded`.

## ADR-001 — PWA на GitHub Pages

**Статус:** accepted (2026-10-25)
**Контекст:** заказчик не разработчик, нужен ввод с iPhone в зале, таблицы и графики, всё бесплатно,
без выделенного сервера. Нативное iOS-приложение требует Mac и $99/год.
**Решение:** PWA (React + TypeScript, Vite), статика на GitHub Pages, иконка на домашнем экране.
**Последствия:** работает офлайн, ноль расходов, Mac не нужен. Ограничения iOS (нет фоновой
синхронизации, нет пуш-уведомлений в старых версиях) принимаем. Тот же фронтенд позже можно
завернуть в Telegram Mini App без переписывания.

## ADR-002 — Данные: локально первично, Google Sheets как хранилище-зеркало

**Статус:** accepted (2026-10-25)
**Контекст:** выбрана Google Sheets как база (привычные таблицы, доступ с компьютера).
Но Web App отвечает 0,3–2 с, а в зале сеть нестабильна.
**Решение:** IndexedDB — оперативное хранилище и источник для UI; Google Sheets через Apps Script —
долговременное хранилище и синк, запись батчами с флагом `pendingSync`.
**Последствия:** быстрый интерфейс и офлайн; нужна аккуратная дедупликация по `id` и `updatedAt`.
URL Web App и токен хранятся в localStorage телефона (в репозиторий не попадают).
Риск: любой, кто узнает URL `/exec`, сможет вызвать API — поэтому обязательный токен в запросе.

## ADR-003 — Без ИИ на старте

**Статус:** accepted (2026-10-25)
**Контекст:** нужен предсказуемый результат и минимум зависимостей.
**Решение:** план считает детерминированный движок правил (`src/core/`). ИИ — отдельная фаза P3
как надстройка: объяснения, нестандартные ситуации. Приложение обязано работать без ИИ.
**Последствия:** нет расходов и утечек ключей на старте; логика покрывается тестами.

## ADR-004 — Стек: Vite + React + TypeScript

**Статус:** accepted (2026-10-25)
**Решение:** SPA на Vite, React 18, TypeScript strict, Vitest для `src/core/`, без UI-библиотек
(свои компоненты, CSS-переменные). Навигация — табы в состоянии, без роутера; frontend-роутер
добавим только если появятся deep links (тогда HashRouter — требование GitHub Pages).
**Последствия:** нужен Node.js на машине, `npm install` / `npm run dev`. Зато типы ловят половину ошибок.

## ADR-006 — MCP-серверы: минимум

**Статус:** proposed
**Контекст:** MCP нужен, чтобы не изобретать команды, но каждый сервер — токены и точка отказа.
**План:** `github` (remote, OAuth) — репозиторий и Actions; `context7` — актуальные доки React/Vite.
Google Sheets работаем через Apps Script Web App, отдельный MCP не нужен.
`filesystem`/`git`/`playwright` не подключаем — дублируют встроенные инструменты.

## ADR-007 — Иллюстрации упражнений и карта мышц

**Статус:** accepted (2026-10-25)
**Контекст:** нужны картинки «как делать» и подсветка работающих мышц, без платных библиотек и без
хранения десятков мегабайт в репозитории.
**Решение:**
1. Фото старт/финиш — из публичного каталога `yuhonas/free-exercise-db` (лицензия Unlicense,
   public domain, 876 упражнений). Файлы не копируем в репозиторий, берём по CDN jsDelivr.
   Соответствие нашим 58 упражнениям — в `src/data/exercise-media.json`, генерируется
   скриптом `tools/match-exercise-media.mjs` (58/58 совпадений).
2. Карта мышц — свой SVG (`src/components/MuscleMap.tsx`): перед/спина, подсветка основной группы
   сплошным акцентом, вспомогательных — полупрозрачным. Не зависит от лицензий и всегда в тон теме.
**Последствия:** первая загрузка картинки — сеть (≈70 КБ на кадр), поэтому в каталоге превью
ленивые, в шторке упражнения — приоритетные. Полный офлайн картинок не гарантируем; текст и карта
мышц работают всегда. Если CDN станет недоступен — карта мышц и подсказки остаются.
