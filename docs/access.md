# Доступ, приватность и масштабирование

Коротко: **данные тренировок никогда не лежат на сервере**, поэтому «взламывать» сайт
нечего. Открытый репозиторий показывает только код. Для тестового периода с друзьями
достаточно ссылки; при желании включается мягкий код доступа одной переменной в GitHub.

## 1. Почему репозиторий открыт

- GitHub Pages **бесплатно** публикует сайты только из публичных репозиториев. Приватный
  репозиторий на бесплатном тарифе Pages не отдаёт (нужен платный GitHub Pro).
- Actions на публичном репозитории бесплатны без лимита минут; на приватном — 2 000 минут в месяц.
- В репозитории нет секретов: ни ключей, ни паролей, ни токенов (`.env*` в `.gitignore`,
  файлов `.env` в проекте нет).
- Сами данные тренировок в репозиторий не попадают: они хранятся в IndexedDB браузера
  на устройстве пользователя.

## 2. Что видит посторонний человек

| Что | Видно? | Почему |
| --- | --- | --- |
| Исходный код | да | как у любого сайта: JS всё равно скачивается в браузер |
| Адрес сайта | да, если знает ссылку | GitHub Pages публичен по своей природе |
| Твои тренировки, вес тела, история | **нет** | они в браузере на твоём телефоне |
| Ключи, токены, пароли | нет | их в коде нет |

У каждого посетителя своя пустая база. Друг, открывший ссылку, увидит приложение
с нуля — твои данные ему недоступны, а его данные не попадут к тебе.

Поисковики не индексируют сайт: в `index.html` стоит `noindex, nofollow`.
Это не защита, просто меньше случайных посетителей.

## 3. Можно ли взломать или украсть

**Взломать — нечего.** Нет сервера, нет базы на сервере, нет логинов, нет платежей.
Сайт — это набор статических файлов. Даже если кто-то откроет консоль браузера,
он увидит только свой пустой IndexedDB.

**Украсть код — теоретически да.** Можно скопировать репозиторий и задеплоить у себя.
Но это верно для любого веб-приложения: код фронтенда всегда приходит в браузер.
Закрытие репозитория почти ничего не меняет — оно скрывает комментарии и историю, а не
приложение. Защита здесь юридическая: файл `LICENSE` («все права защищены») фиксирует,
что копирование и коммерческое использование без разрешения запрещены.

**Настоящий риск — не «взлом», а утечка секрета.** Появится, когда подключим Google Sheets:
токен должен жить в localStorage пользователя или в GitHub Secrets/переменных, но не в коде.
Правило зафиксировано в `AGENTS.md`.

**Важнее всего:** включить двухфакторную аутентификацию на GitHub. Угон аккаунта — самый
реалистичный способ испортить проект. Данные пользователей при этом всё равно не в облаке.

## 4. Друзья на тест

### Вариант 0 — просто ссылка (0 работы)
Даёшь `https://romanvaks12-oss.github.io/gym-coach/`. Каждый получает свою пустую базу,
твои данные не видны. Минус: ссылку может открыть любой, кто её получит.

### Вариант 1 — мягкий код доступа (уже сделан)
Экран «Тестовый доступ» появляется, только если задан код. Иначе приложение открывается
сразу, как сейчас.

Как включить (2 минуты, без программ):
1. GitHub → репозиторий `gym-coach` → **Settings** → **Secrets and variables** → **Actions**.
2. Вкладка **Variables** → **New repository variable**.
3. Имя: `INVITE_CODE`, значение: любой код (например, `romka-2026`).
4. Перезапустить деплой: **Actions** → `Deploy to GitHub Pages` → **Run workflow**.

Друг открывает ссылку, вводит код один раз — дальше приложение работает как обычно,
в том числе офлайн. Чтобы закрыть доступ: удалить переменную и перезапустить деплой
(у уже вошедших код останется в браузере, но новые люди попасть не смогут).

**Ограничение, честно:** код лежит в JS-бандле, технически его можно вытащить.
Это шторка от случайных людей, а не замок. Для друзей — достаточно.

### Вариант 2 — настоящая проверка на сервере (если понадобится)
Cloudflare Worker (бесплатно, без карты) с паролем и подписанной cookie перед статикой:
код проверяется на сервере, доступ можно отозвать, вести список людей. Работы на 1–2 часа,
бесплатно в пределах free tier. Делаем, если тестеров станет больше 10–20 или понадобится
«отключить конкретного человека».

### Вариант 3 — копия сборки (zip)
Не рекомендуем: обновления придётся раздавать вручную, у каждого будет своя версия,
и баги будут воспроизводиться по-разному.

**Рекомендация:** для 3–10 друзей — вариант 0 или 1. Переходить на вариант 2 только
по реальной потребности.

## 5. Масштабирование

| Этап | Когда | Что появляется | Цена |
| --- | --- | --- | --- |
| A. Личное приложение | сейчас – 2 мес | локальные данные, аналитика, офлайн | 0 |
| B. Синк с Google Sheets | 2–4 мес (P2.5) | у каждого своя таблица и свой токен, сервера у нас нет | 0 |
| C. Аккаунты и синк между устройствами | если реально нужно | Supabase free (auth + Postgres 500 МБ) или Cloudflare D1 | 0 |
| D. «Релиз» на пару месяцев | после стабильной работы | версии, бэкапы, приватность, инструкция | 0 |

Что уже готово к росту:
- `pendingSync` в записях — очередь на синхронизацию;
- `schemaVersion` в настройках и экспорт JSON — миграции с бэкапом;
- вся логика в `src/core/` без сети и DOM — легко тестировать и переносить;
- код доступа включается/выключается без правки кода.

Чего не будет: сторонних трекеров, рекламы, аналитики третьих лиц, платных сервисов и
хранения паролей у себя.
