# Состояние проекта

Обновлено: 2026-10-26

## Сейчас

P1 и P2 готовы, репозиторий на GitHub, деплой на Pages через Actions. Работает офлайн.
Сделано после разбора с «фитнес-тренером»:
- планировщик — сплит-скелет (всё тело / верх / низ) + фильтр восстановления: крупные группы
  (ноги, спина, широчайшие, грудь, плечи) не грузим 2 дня, мелкие — 1; болезненность 7–10 исключает
  группу; бонус ротации `upper → lower`; тип прошлой тренировки в `meta.lastDay`, «всё тело» —
  запасной вариант при наличии истории (ADR-008);
- убраны разминочные подходы из экрана тренировки, в лог идут только рабочие; вес тела в брифе
  сохраняется в `body`; подтягивания 2–3 повтора × максимум 3 подхода, прогрессия по повторам,
  тоннаж = (вес тела + доп. вес) × повторы; планка и прогулка фермера — в секундах (ADR-009);
- карта мышц перерисована в стиле анатомического плаката (перед + спина, сетка 200×460, левая
  половина зеркалится): контурная линия, отдельные «мясные» зоны — дельты, верх/низ груди, пресс
  8 сегментов + косые + зубчатые, трапеции, широчайшие, разгибатели, трицепс/бицепс бедра, ягодицы,
  икры; подпись «контур — в память о Вадиме Иванове» (ADR-007 обновлён);
- план-таблица не расползается на 390 px (`table-layout: fixed`);
- записанный подход можно **исправить или удалить**: «правка» в списке подходов → меняются вес,
  повторы и RPE, номер подхода сохраняется; удаление перенумеровывает остальные (ADR-010);
- защита от опечаток: жёсткие пределы (вес ≤ 400 кг, повторы 1–100, время ≤ 1800 с, RPE 1–10,
  дробные повторы запрещены) и мягкое предупреждение «вес резко больше прошлого» с подтверждением
  вторым нажатием — 112 вместо 12 больше не улетает в базу молча;
- **P2, экран «Прогресс»** (`src/core/analytics.ts` + `ProgressScreen`): тоннаж по неделям (8 недель,
  пустые недели — честные нули), оценка 1ПМ по Эпли по неделям с трендом (медиана 2 последних
  недель против 2 предыдущих), объём по группам мышц за 4 недели (синергист — 0,5 подхода),
  вес тела по замерам с изменением и скоростью, личные рекорды с пометкой свежих;
- **доступ и приватность** (`docs/access.md`, ADR-011): репозиторий публичный (Pages бесплатно),
  данные только в браузере, мягкий код доступа `INVITE_CODE` — по умолчанию выключен, включается
  переменной в GitHub Actions; лицензия «все права защищены», сайт закрыт от индексации;
- **P2.5, зеркало в Google Sheets** (ADR-012): Apps Script Web App (`integrations/apps-script/Code.gs`,
  действия `ping`/`pull`/`push`, `LockService`, даты текстом), клиент `src/storage/sync.ts`,
  слияние по `id` в `src/core/merge.ts` (свежий `updatedAt` побеждает, но `pendingSync` главнее),
  экран «Настройки» с URL/токеном, «Придумать токен», проверкой связи, ручным синком и счётчиком
  неотправленного, тихий автосинк после тренировки с кнопкой «Отправить ещё раз»;
  пошаговая инструкция для не-разработчика — `docs/sheets-setup.md`;
- 97 тестов зелёные (27 логики + 28 стресс/границ + 24 аналитики + 7 слияния + 10 разбора
  строк Sheets + 1), `typecheck` и `build` чистые.
  Стресс-набор нашёл реальный баг: при болезненности 10/10 по всем группам возвращался пустой план
  вместо «день отдыха» — исправлено в `plan.ts`.

## Аналитика

`src/core/analytics.ts` — чистые функции, без DOM и сети: `epley1rm` (только 1–15 повторов и вес
больше нуля), `totalTonnage` (разминка и мусор не считаются), `weeklySummaries`, `e1rmSeries`,
`trendOf`, `personalBests`, `muscleVolume`, `bodySeries`, `bodyChange`. Неделя — понедельник–воскресенье
по локальной дате; переход через год покрыт тестами.

## Синхронизация

`src/storage/sync.ts` — сеть только здесь: `isConfigured` (нужен https-URL на `/exec` + токен),
`testConnection`, `syncNow` (push → полный pull → merge → пометка отправленных), `pendingCount`,
таймаут 20 с. Ответы Apps Script приходят без HTTP-статусов, поэтому читаем `{ok,error}` из тела;
понятные тексты ошибок — в `errorText`. Разбор строк таблицы (`parseWorkoutRow`/`parseSetRow`/
`parseBodyRow`) отбрасывает мусор и невозможные значения, запятую в числах понимает, вес 0 считает
законным (своё тело). Токен и URL — только в `localStorage`, в репозитории их нет.

## Стресс-тесты

`src/core/__tests__/edge-cases.test.ts`: битые и NaN-данные в истории, отрицательные и нереальные
значения, границы веса/повторов/секунд/RPE, будущие даты, упражнения не из каталога, «все мышцы
болят», вес тела 1123 кг. Проверяем, что движок не падает, не выдаёт NaN и не отдаёт абсурд.

## Ручная проверка

`npm run dev` → `http://127.0.0.1:5173`, вьюпорт 390×844:
бриф с весом тела → «Собрать план» → два варианта (низ/верх и разумный порядок) →
«Начать» → «Записать подход» → таймер → «Завершить» → сводка.
Повторный бриф с болезненностью 7+ убирает упражнения на эту группу; после завершения тренировки
следующий план не предлагает тот же день верха/низа.

Правка и защита от опечаток (проверено на проде):
записать подход 12 кг × 8 → ввести 112 → «Записать подход» показывает «Вес 112 кг резко больше
прошлого (12 кг) — похоже на опечатку. Всё верно?», кнопка меняется на «Всё верно, записать» →
нажать «правка» у второго подхода → поменять 112 на 22 → «Сохранить изменения» (номер подхода и
список не дублируются) → «Удалить подход» убирает строку и перенумеровывает остальные →
«Следующее упражнение →» и «← пред.» возвращают к предыдущему упражнению с его подходами.

Вёрстку без кликов удобно смотреть на `/preview.html` (страница только для dev, в сборку не входит):
план, экран тренировки и карта мышц сразу. Быстрые сценарии: `?demo=warn` (12 → 112 →
предупреждение), `?demo=edit` (записан подход, открыта правка), `?view=progress` (экран прогресса
на демо-истории за 8 недель с пропущенной неделей), `?view=map` (четыре варианта подсветки карты
мышц), `?view=settings` (экран синка).

Синк (что проверено): разбор строк таблицы и настроек — 10 тестов (`src/storage/__tests__/sync.test.ts`),
слияние — 7 тестов (`src/core/__tests__/merge.test.ts`); экран «Настройки» проверен в браузере
(бейдж «вкл/выкл», поля, кнопки не вылезают на 390 px, токен генерируется). Живой обмен с таблицей
ещё не проверялся — нужен свой Web App: «Настройки» → URL и токен → «Сохранить» → «Проверить связь»
должно дать «Связь есть — таблица отвечает» → «Слить сейчас» пишет «Готово: отправлено N, получено M»,
счётчик «Ждут отправки» обнуляется. После «Завершить тренировку» на сводке — «Данные в локальной
базе и в Google Sheets (N записей)»; без настроек — «Синк не настроен»; при ошибке — «Отправить ещё раз».

Аналитика (проверено на dev и на демо-данных): после одной тренировки 60 кг × 8 на «Прогрессе»
тоннаж недели 480 кг, 1 тренировка за 4 недели, 1 подход, вес тела 78 кг, рекорд «≈ 76 кг»
(60 × (1 + 8/30)), 8 столбиков недель. Пустая база показывает честное «Пока пусто».

Код доступа: `VITE_INVITE_CODE=test123 npm run dev` → экран «Тестовый доступ», неверный код даёт
«Код не подошёл», верный пускает и больше не спрашивает (localStorage). Без переменной экрана нет.
