# Стек: варианты, рекомендация, скилы и MCP

## Варианты площадки

| Вариант | Ввод в зале | Таблицы/графики | Офлайн | Цена | Сложность | Главный риск |
|---|---|---|---|---|---|---|
| **PWA** (веб-приложение, иконка на iPhone) | хорошо | отлично | да | 0 (GitHub Pages) | средняя | нужно аккуратно с iOS-квирками |
| **Telegram-бот** | отлично (чат под рукой) | плохо (текст, без графиков) | нет | 0 (Workers free) | низкая | интерфейс упирается в чат; нужен постоянный хостинг |
| **Telegram Mini App** | хорошо | отлично | частично | 0 | средняя+ | лишний слой Telegram, публичный HTTPS |
| **Google Sheets + Apps Script** | средне | отлично (это и есть таблица) | нет | 0 | низкая | UX слабый, версии скриптов неудобны |
| **Нативное iOS** | отлично | отлично | да | $99/год + Mac | высокая | нужен Mac и Xcode — не наш путь |

## Рекомендация

**PWA на GitHub Pages, данные локально (IndexedDB), правила — чистый JS/TS, ИИ — опциональная надстройка.**

Почему:
- Таблицы и графики — родная стихия веба, а не чата. Заказчик любит таблицы → PWA выигрывает.
- Нет сервера: статика на GitHub Pages, аккаунты/бэкапы/оплата не нужны. Ничего не «упадёт ночью».
- Офлайн в зале: интернет в подвале зала часто плохой. Service worker + IndexedDB решают.
- Mac не нужен. Нативное приложение без Mac и $99/год на iPhone не поставить.
- Апгрейд-путь: тот же код можно позже открыть как Telegram Mini App, не переписывая.

Порядок роста: **P0 локально** → **P1 правила** → **P2 аналитика** → **P3 ИИ через прокси** → **P4 синк**.
ИИ на старте не нужен: 90 % ценности даёт детерминированный движок, а он бесплатный и предсказуемый.

## Реальность free tier (проверять при старте)

- **GitHub Pages**: статика, бесплатно, свой домен опционально. Приватность: репозиторий публичный
  или данные всё равно живут только в телефоне — второй вариант нормален.
- **GitHub Actions**: 2000 мин/мес для приватных репозиториев, безлимит для публичных. Годится для
  бэкапа и сборки, **не** для интерактивных ответов (задержка + лимиты).
- **Cloudflare Workers**: 100k запросов/день бесплатно — хватит как прокси к LLM с ключом в secrets.
- **Supabase free**: пауза проекта после недели простоя — помнить, если выберем облако.
- **LLM free tier**: Google Gemini, Groq, OpenRouter (бесплатные модели). Для одного пользователя — с запасом.
- Ключ LLM для личного приложения допустимо держать в localStorage телефона (риск — только своя потеря ключа),
  но аккуратнее и чище — прокси на Worker.

## Скилы проекта (`.opencode/skills/`)

| Скил | Зачем |
|---|---|
| `training-domain` | методика: недельные объёмы, двойная прогрессия, RPE↔RIR, окна восстановления, разгрузки, safety-стопы, правила подбора упражнений |
| `pwa-iphone` | manifest, service worker, safe-area, `100vh`-квирки iOS, зум при фокусе инпута, standalone-режим, IndexedDB |
| `data-analytics` | схема данных, миграции без потерь, формулы (1ПМ, тоннаж, тренды), корректная агрегация по неделям |
| `free-deploy` | GitHub Pages, Actions, Cloudflare Workers/D1, лимиты, секреты, откат |
| `llm-coach` | промпты тренера, structured JSON output, валидация ответа, fallback на правила, стоимость |
| `telegram-bot` | только если пойдём в бота/мини-апп: Bot API, webhook, клавиатуры |

Стартовый набор — первые четыре + `llm-coach` на фазе P3. Не плодим скилы «на всякий случай»:
каждый висит в контексте.

## MCP-серверы

| MCP | Тип | Нужен | Зачем |
|---|---|---|---|
| `context7` | remote | да | актуальная документация React/Vite/Bot API — без устаревших сниппетов |
| `github` | remote (OAuth) | да | issues/PR/Actions, работа с репозиторием без локального git-зоопарка |
| `cloudflare` | remote | по выбору | воркеры, D1/KV, деплой прокси к LLM |
| `supabase` | remote | по выбору | если данные в облаке: SQL, миграции, типы |
| `playwright` / chrome | local | нет | встроенные browser-инструменты OpenCode уже дают скриншоты и мобильный вьюпорт |
| `filesystem`, `git`, `sequential-thinking` | local | нет | дублируют встроенные инструменты, только засоряют контекст |
| `notion` | remote | опционально | если захочется вести дневник решений вне репозитория |

Правило: **не больше 2–3 MCP одновременно.** Каждый сервер — это токены и лишние точки отказа.
