# Gym Coach — правила работы

## Контекст

Проект: личный помощник по силовым тренировкам (веб-приложение, iPhone в приоритете).
Стек: определяется в `docs/stack.md`. Общение по-русски, код и имена файлов — по-английски.
Заказчик не разработчик: весь код пишет агент, объяснения — простым языком.

## Железные правила

1. **Сначала план на 3–7 пунктов, потом код.** Маленькие диффы, не переписывать файлы целиком без причины.
2. **Бесплатно.** Только free tier / статика / GitHub Pages. Ничего, что требует карты или выделенного сервера.
3. **Секретов в репозитории нет.** API-ключи — в localStorage пользователя, в GitHub Secrets или в переменных окружения воркера.
4. **Логика отдельно от UI.** Правила тренировок — чистые функции в `src/core/`, без обращений к сети и DOM. Покрываем тестами.
5. **Данные пользователя неприкосновенны.** Любая миграция схемы — с обратной совместимостью и авто-бэкапом.
6. **Медицинская безопасность.** Приложение — не врач: острые болей, суставы, «стреляет» → совет обратиться к врачу, тренировку не назначаем.
7. В конце задачи — обновить `docs/state.md` (3–7 строк); важное решение — в `docs/decisions.md`.

## Токен-дисциплина

- Сначала `grep`, потом `read` с `offset/limit`.
- Не дублировать в ответе код, который уже есть в файле — ссылаться на путь и строки.
- Одна задача = одна сессия. Большие тексты — в `docs/`, не в чат.
- Логи и дампы в чат целиком не вставляем: 10–20 значимых строк.

## Проверки перед «готово»

- `npm run typecheck` и `npm test` (если есть) — зелёные.
- UI проверяется в браузере в мобильном вьюпорте 390×844 (Safari iPhone), а не «на глаз».
- Сценарий ручной проверки — в `docs/state.md`.

## Запрещено без явного согласия

- Добавлять платные сервисы, аналитику, трекеры.
- Менять схему хранения данных без бэкапа.
- Пушить в `main` без показа диффа.
